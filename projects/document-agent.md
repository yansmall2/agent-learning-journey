# 主项目：有引用与评测的文档研究助手（计划）

目标：用户针对一组公开、可使用的文档提问，系统检索相关内容，必要时调用工具进行多步处理，给出可追溯引用；证据不足时明确说不知道。这个项目尚未实现，下面是设计，不是成果。

## 分阶段

1. 建立最小数据集和直接检索基线：选择许可清晰的文档，保存来源和版本；记录分块方法，并返回原文片段与来源。
2. 实现 RAG：可替换 embedding/检索器，生成带引用回答，覆盖无答案问题；先跑通单轮流程。
3. 增加 Agent：将检索封装为工具，定义参数、状态、最大调用次数、失败和超时策略；测试工具错误及停止条件。
4. 工程化：FastAPI 接口、配置、日志、自动化测试和可复现运行说明。真实模型接口依赖密钥时，提供模拟模式供基础测试。
5. 评测与改进：创建与开发样例分离的人工核验数据集，先做 20 条小样，再逐步扩至 50–100 条，覆盖单文档、多文档、无答案。对比基础检索和改进方法，不预设提高幅度。

## 评测口径

至少记录每个问题、人工参考证据、检索结果和回答；计算 Recall@k（有标注的相关片段被召回比例）、人工抽查回答正确性及引用是否支持结论，记录 p50/p95 延迟、每次调用的成本或 token。说明数据集大小、标注方法、计算口径及失败案例。最终报告对比同一批问题、同一设置的基线和改进，避免拿不同条件比较。
