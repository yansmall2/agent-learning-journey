# 第 1 天：离线 Agent 工具执行器

状态：待完成。建议用时 2～3 小时，不需要模型 API、数据库或 Agent 框架。先独立尝试 30～45 分钟；可以查文档、请求提示，记下 AI 帮助过哪些地方。

## 任务

实现一个工具执行器，读取包含多条调用的 JSON 文件，按输入顺序执行，并返回每条结果。通过注册表管理工具；不使用 `eval`、`exec` 或 `globals()`。

支持两个工具：

- `add`：参数 `a` 和 `b` 均为 JSON 数字，返回两数之和；布尔值不作为数字。
- `lookup`：参数 `key` 是字符串，从本地字典 `{"rag":"检索增强生成", "agent":"能调用工具的系统"}` 中精确查询。

示例输入：

```json
{
  "calls": [
    {"id": "1", "name": "add", "arguments": {"a": 2, "b": 3}},
    {"id": "2", "name": "lookup", "arguments": {"key": "rag"}},
    {"id": "3", "name": "unknown", "arguments": {}},
    {"id": "4", "name": "add", "arguments": {"a": 7, "b": 1}}
  ]
}
```

示例输出：

```json
{
  "results": [
    {"id": "1", "ok": true, "result": 5},
    {"id": "2", "ok": true, "result": "检索增强生成"},
    {"id": "3", "ok": false, "error": "unknown_tool"},
    {"id": "4", "ok": true, "result": 8}
  ]
}
```

## 行为要求

1. 顶层必须是 JSON 对象，`calls` 必须为数组，最多 10 条；不满足条件时整个请求报错、程序以非零状态退出。空数组是合法输入。
2. 每条调用必须包含非空字符串 `id`、字符串 `name`、对象 `arguments`。缺失或无效的 id 在该条输出中用 `null`；重复 id 的后续调用报 `duplicate_id`。
3. 未知工具、缺参数、参数类型错误、查无 key 均只影响当前调用，后续调用必须继续执行。错误码分别使用 `unknown_tool`、`invalid_arguments`、`not_found`；字段结构有误使用 `invalid_call`。
4. 文件不存在或 JSON 无法解析时，显示清晰错误并以非零状态退出。避免将异常堆栈作为唯一的用户提示。
5. 对正常调用、未知工具、非法参数、查询不到、失败后继续执行、空数组写自动化测试。增加重复 id、布尔型数字与请求超限测试更好。
6. 写 README：运行命令、测试命令、设计思路和已知限制；提交时不包含虚拟环境或密钥。

## 验收和进阶

给定示例输出应依次是 `5`、`检索增强生成`、`unknown_tool`、`8`。完成后，尝试不依赖 AI 解释工具注册和错误隔离如何实现，并新增一个 `multiply` 工具及其测试。你可以把代码、测试结果和最难的地方交给指导老师做代码审查。

本题是模拟工具执行层，调用数据由本地 JSON 提供，不是完整的 LLM Agent；后续再连接模型、观察结果和 Agent 循环。
